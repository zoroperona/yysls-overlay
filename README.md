# 燕云浮层提醒器

《燕云十六声》Windows 桌面辅助工具。识别屏幕上的 Buff 和奇术图标，在独立浮层显示倒计时并播放提醒音。支持同时勾选多个项目，共享 Debuff 栏区和奇术区、各自独立计时；支持选择是否让截图 / 录屏捕获浮层。

## 已支持的流派与技能

这里的“支持”指下表中的图标监控，不代表完整流派循环或自动操作。流派称呼按提供的信息记录，不推断未确认的归属。

| 流派 / 分类 | 监控项 | 类型 | 配置时长 | 提醒方式 |
| --- | --- | --- | --- | --- |
| 威威 | 威威易伤 | Buff | 16 秒 | 效果临近结束提醒 |
| 无名 | 真气失衡 | Buff | 15 秒 | 效果临近结束提醒 |
| 尘尘 | 失魂落魄 | Buff | 21 秒 | 原有失魂识别、刷新与临近结束提醒 |
| 通用奇术 | 骑龙回马 | 奇术 | 12 秒 | 确认可用时提醒；确认使用后显示冷却 |
| 通用奇术 | 千灯一月 | 奇术 | 40 秒 | 确认可用时提醒；确认使用后显示冷却 |
| 通用奇术 | 笛子（沿用原界面称呼） | 奇术 | 24 秒 | 奇术共享区搜索、可用及重复提醒 |

名称、时长和图标路径定义在仓库根目录的 [skills.json](skills.json)。程序启动时读取；修改后重启软件。`category` 决定搜索哪个共享区域：`debuff` 为 Debuff 栏区，`qishu` 为奇术区。`cd` 对 Buff 表示**持续时间**，对奇术表示**使用后的冷却时间**，单位均为秒。配置表中的默认时长在启动 / 开始监测时生效。

## Windows 安装与运行

1. 安装 [Python 3.12（64 位）](https://www.python.org/downloads/windows/)，保留 Python Launcher、pip 与 Tcl/Tk 选项。
2. 下载完整仓库（Code → Download ZIP），或者下载 Release 的 `yysls-overlay.zip`，解压到普通文件夹。不要只复制主 Python 文件。
3. 双击 `start-windows.bat`。首次运行创建 `.venv` 并联网安装依赖，以后直接启动。
4. 打开主界面的「监控列表」，勾选需要的项目。默认保留原有失魂和笛子，新项目需自行勾选。
5. 框选整个「Debuff 栏区」和整个「奇术区」，然后点击「开始监测」。只使用一种类别时，仅需设置该类别区域。

也可在 PowerShell 手动运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe buff_reminder_v2_dizi_hotkey.py
```

## 两个共享区域，多项独立计时

软件只需要两个选区：

| 共享区域 | 配置类别 | 在区域内搜索的技能 |
| --- | --- | --- |
| Debuff 栏区 | `debuff` | 威威易伤、真气失衡、失魂落魄 |
| 奇术区 | `qishu` | 骑龙回马、笛子、千灯一月 |

在主界面或「监控列表」点击「框选 Debuff 栏区」「框选奇术区」。确定后 5 秒冻结截图，鼠标框住**整个栏区**、四周留少量余量，Enter 确认，Esc 取消。不用逐个框选图标，也不用逐技能校准亮起状态；新增同类别技能会自动使用已有选区。

勾选的技能按 `category` 在对应区域内匹配原图，图标在区域内换槽、顺序变化时会重新定位。每项状态与计时互不替代，开启多个项目后同时监控。框选的是整条栏区，不要只圈住其中一个图标，也尽量不要把聊天或其他界面放入选区。

修改勾选或重选区域会停止监测，完成后重新开始。NumLock 默认全局暂停 / 继续，可在主界面更改。整个栏区移到选区外，或分辨率 / UI 布局变化导致选区不再覆盖栏区时，重新框选对应区域。

失魂保留原有原图身份匹配、搜索与追踪；它使用的仍是共享 Debuff 栏区。「模板与遮罩」三项保持留空即可。笛子与另外两个奇术统一在共享奇术区内搜索，保留笛子的独立音效和重复提醒设置。

Buff 连续确认亮起后建立时间轴，相对亮度连续跃升后确认刷新；不是直接读取游戏倒计时数字。如果启动时 Buff 已经生效一段时间，首次推算可能偏晚，应等待下一次施加 / 刷新。奇术必须先确认亮起，再连续确认变暗，才开始冷却；启动时已经在冷却不会猜测剩余秒数。图标或整条奇术栏消失不会被当作技能使用。到零只表示推算到期，实际重新可用仍以图标变亮确认。

### 从 v2.6.0 升级

已保存的敌方 Buff 栏选区继续作为共享 Debuff 栏区使用。请重新框选一次**完整奇术区**；旧版每技能选区、单独笛子选区和校准数据不再作为监测输入，不会自动把单个图标的小框当作整个奇术区。勾选状态、浮层和音效偏好保留。

## 浮层、声音与录屏

「常用设置 → 浮层位置 / 音效设置」可切换文字 / 图标模式。图标模式按配置表顺序展示勾选项目的多个槽位，分别绘制倒计时；未确认起始时刻显示 `?`。点击「预览并拖动」调整位置。

新增项目使用通用电子提示音，文字提醒包含技能名，避免误播“笛子好了”等其他技能语音。同一检测轮内的多个文字提醒合并显示。主界面「声音提醒」「画面提醒」总开关对所有项目生效。

默认不允许截图或录屏捕获浮层。需要录制时勾选「允许截图/录屏捕获浮层」，保存或预览后生效。录屏软件请选择显示器 / 桌面捕获，将浮层移出检测区域；遮挡时对应区域内的监测跳过该帧，另一未遮挡区域继续监测。

原有失魂、笛子的详细设置见 [浮层与音效说明](docs/reminder-controls.md)。

## 自己添加技能、Buff 或奇术

无需改 Python 代码，通用识别适用于**透明背景、白色图案**的图标。彩色照片、无透明通道或复杂动态图标不属于当前通用检测器的支持范围。

1. 准备目标的透明背景 RGBA PNG，只把需要的一张图放入 `assets/icons/`，例如 `assets/icons/my_qishu.png`。不要复制整个素材库，也不要用带角色名、聊天或账号信息的截图。
2. 编辑根目录 `skills.json`，在 `skills` 数组中追加项目。保持合法 JSON，项目之间加逗号，最后一项后不要加逗号。示例中的 `my_qishu.png` 需由你自己提供：

```json
{
  "id": "my_qishu",
  "name": "我的奇术",
  "school": "通用奇术",
  "kind": "qishu",
  "category": "qishu",
  "cd": 30,
  "icon": "assets/icons/my_qishu.png"
}
```

添加 Debuff 时使用 `"kind": "buff"` 和 `"category": "debuff"`，`cd` 填效果持续时间；添加奇术时使用 `"kind": "qishu"` 和 `"category": "qishu"`，`cd` 填使用后的完整冷却时间。根级 `version` 使用 `2`。

| 字段 | 规则 |
| --- | --- |
| `id` | 稳定且唯一的小写英文标识，可含数字、下划线，以字母开头；不要复用其他项目的 ID |
| `name` | 软件中展示和提醒使用的技能名 |
| `school` | 流派 / 分类说明；可省略，默认“自定义” |
| `kind` | `buff` 或 `qishu`，决定计时语义 |
| `category` | `debuff` 或 `qishu`，选择共享搜索区域；须与上面的 `kind` 对应 |
| `cd` | 大于 0、不超过 3600 的秒数，支持小数 |
| `icon` | 仓库内 PNG 的相对路径，使用 `/`；不允许绝对路径或 `..` |

3. 保存后重启软件，打开「监控列表」，新项目自动出现。
4. 勾选后开始监测。程序会在该类别已保存的区域内寻找新图标，无需新增选区；尚未设置该类别区域时，先框选整个栏区。

新增项目**不要填写 `engine`**，默认走共享区域的通用检测器。原有 `loss` / `dizi` 的 `engine` 用于兼容失魂专用追踪、笛子声音与重复提醒；它们也遵循 `category` 的共享选区。请保留内置项目的 ID、类型、类别、引擎和原图路径。通用项目可增删；改 ID 会视为新项目，需要重新勾选。

## 配置保存与隐私

两个共享选区、勾选状态和浮层设置保存在 `%APPDATA%\尘Buff提醒器_追踪明度版\config.json`，不写回公共 `skills.json`。更新代码不会清空该用户目录。区域设置只保存坐标，不保存框选时的截图。运行时原图匹配自动搜索位置和尺寸。

识别和播放音效在本机进行，运行时不上传画面、不调用在线语音服务；安装依赖需要联网。「保存诊断截图」会在本机保存游戏画面，反馈或发布前请自行检查个人信息。素材来源见 [ASSETS.md](ASSETS.md)。

自动测试覆盖配置校验、同一区域内多个图标识别与换槽、类别隔离、亮暗转换、遮挡保护、计时与资源打包。测试素材为技能原图、单个裁剪图标与合成画面；通过测试不代表实战准确率。Windows 游戏内多屏、实际冷却遮罩、复杂背景、Buff 换槽及录屏效果仍需实机验证。
